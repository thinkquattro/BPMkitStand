# GAP-001 — `stand_scheme` / `verify_tls` нельзя задать из формы регистрации

- **Область:** хаб (форма регистрации), реестр
- **Приоритет:** высокий
- **Заведён:** 18.08.2026 (живая приёмка агента на Linux)
- **Статус:** открыт

## Симптом

Оператор регистрирует стенд за TLS кнопкой «Зарегистрировать стенд», заполняет
все поля формы — и получает `http: down` при живых `process` и `db`. В форме нет
ни поля схемы, ни флага проверки сертификата, а без них проба уходит на
`http://` и на TLS-порт не попадает.

Единственный способ настроить — правка `projects.json` руками:

```json
"stand_scheme": "https",
"verify_tls": false
```

## Почему так

Форма построена по **фиксированному белому списку полей** — на клиенте и на
сервере независимо:

- `standkit_hub/web/app.js::_REGISTER_FIELD_NAMES` — что собирается с формы;
- `standkit_hub/server.py::_REGISTER_ALLOWED_FIELDS` — что сервер готов принять
  и записать в `Stand`.

Поля `stand_scheme` / `verify_tls` появились в модели в 0.7.0
(`standkit/models.py::Stand`), но в оба списка не попали: белый список — часть
контура безопасности регистрации (всё, чего в нём нет, в реестр не пишется даже
если клиент это прислал), и расширять его «заодно» с фиксом пробы было бы
изменением поверхности API мимо ревью.

## Что сделать

1. Добавить `stand_scheme` (`select`: `http` / `https`, по умолчанию `http`) и
   `verify_tls` (чекбокс, по умолчанию включён) в оба списка и в разметку формы.
2. `verify_tls` — булев, а `collectRegisterPayload` сейчас берёт `input.value`
   и пропускает пустые строки: чекбокс требует отдельной ветки (`checked`),
   иначе «выключено» приедет как отсутствующее поле и молча даст дефолт `true`.
3. Показывать чекбокс только при `stand_scheme=https` — для `http` он не значит
   ничего и путает.
4. Предупредить в подсказке поля, что `verify_tls: false` — послабление для
   дев-контуров с self-signed, а не для прод-стендов.

## Критерий приёмки

Стенд за TLS с self-signed сертификатом регистрируется **целиком из формы**, без
ручной правки `projects.json`, и сразу показывает `http: ok`. Повторное открытие
формы/редактирование не теряет выставленные значения.
