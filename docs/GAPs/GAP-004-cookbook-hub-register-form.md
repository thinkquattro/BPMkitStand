# GAP-004 — кукбук не описывает поля формы «Зарегистрировать стенд»

- **Область:** документация (`standkit_hub/web/cookbook.html`)
- **Приоритет:** средний
- **Заведён:** 18.08.2026
- **Статус:** ✅ закрыт — 0.8.0, PR #34
- **Как закрыт:** в кукбуке (раздел 04 «Реестр стендов») появился подраздел
  «Модалка «Зарегистрировать стенд» — поле за полем»: врезка про то, что при
  `transport=agent` пробы и старт/стоп делает агент по СВОЕЙ записи, таблица
  по всем полям формы (включая появившиеся `stand_scheme`, `verify_tls`,
  `redis_host`/`redis_port`, `logs_dir`, `agent_ca`, `agent_verify_tls`),
  плитка «раньше это правили в JSON руками — больше нет» и напоминания про
  чтение реестра агента при старте и про fail-closed на `0.0.0.0`.
  Требование анонимизации выполнено: реальное имя стенда заменено на `stand-a`
  во всём файле, включая производные ссылки на секреты.

## Симптом

В кукбуке есть скриншот модалки «Зарегистрировать стенд» и раздел «Регистрация ≠
провижининг», но **пофайлового разбора полей нет**. Оператор, регистрирующий
стенд за агентом, спотыкается на каждом втором поле:

- ставит в «Agent URL» `https://…`, хотя агент поднят с `--insecure` (HTTP);
- пишет в «Host» `127.0.0.1`, не понимая, что это адрес **с точки зрения хаба**,
  а не хоста стенда;
- выбирает «Хостинг: docker» и получает ошибку валидации, потому что не заполнил
  `docker_container`/compose-поля — хотя при `transport=agent` бэкенд на стороне
  хаба вообще не вызывается;
- оставляет пустым `stand_dir` и получает `stand_dir не может быть пустым`, не
  зная, что для agent-стенда это путь **на удалённом хосте**.

## Почему так

Ключевой факт нигде не сформулирован: при `transport=agent` пробы и
старт/стоп выполняет **агент по своей записи реестра**
(`standkit_hub/client.py::FederatedClient.status` просто проксирует
`/stand/<name>/status`), а запись в реестре хаба нужна для маршрутизации и для
ссылки «Открыть стенд». Без этого поля формы читаются как настройки самого
стенда, и половина значений заполняется «по смыслу», а не по назначению.

## Что сделать

Добавить в кукбук раздел «Модалка «Зарегистрировать стенд» — поле за полем» с
таблицей ниже (примеры анонимизированные) и врезкой про `transport=agent`.

| Поле | Что вписать | Зачем |
|---|---|---|
| Имя стенда | `stand-a` | Должно **точно совпадать** с именем в реестре агента — уходит в URL `/stand/stand-a/status` |
| Транспорт | `agent` | Стенд на другом хосте; `local` — стенд на этой же машине |
| Хостинг | `kestrel` | При `transport=agent` хаб бэкенд не вызывает. Выбор `docker`/`k8s`/`iis` включит валидацию и потребует профильные поля |
| Agent URL | `http://example-host:8765` | Схема — **как реально слушает агент**: `--insecure` → `http://`, `--tls-cert/--tls-key` → `https://` |
| Ссылка на секрет агента | `standkit:stand-a:agent-token` | Обязательна, иначе `не задан agent_url/agent_secret_ref`. Значение — на стороне хаба, см. [GAP-005](GAP-005-cookbook-hub-side-secrets.md) |
| Каталог стенда | `/opt/bpmsoft/stand-a` | Обязателен валидацией; путь **на удалённом хосте**, с ним работает агент |
| Host / Port | `example-host` + порт, проброшенный наружу | Только для ссылки «Открыть стенд». `127.0.0.1` здесь — это машина оператора |
| Тип БД / DB host / port / name | можно оставить пустыми | Пробу БД делает агент по своему реестру |

Дополнительно к разделу:

- врезка «что задаётся только правкой `projects.json`» — `stand_scheme`,
  `verify_tls`, `redis_host`/`redis_port` (до закрытия
  [GAP-001](GAP-001-registry-fields-out-of-hub-form.md) и
  [GAP-003](GAP-003-redis-endpoint-in-extra.md));
- напоминание, что реестр агента читается **при старте** — после правки JSON
  агента надо перезапустить;
- отдельная строка про `--insecure`: отказ старта на `0.0.0.0` без TLS —
  это сработавшая fail-closed проверка (`validate_bind_security`), а не сбой.

## Отдельно: анонимизация примеров

В кукбуке фигурировало реальное имя стенда заказчика — в таблице соответствия
ссылок на секреты и в рецепте регистрации. Кукбук публичный: заменено на
`stand-a` / `client-uat`, и это правило для всех новых примеров. Менять надо
согласованно: имя стенда тянет за собой ссылки на секреты
(`standkit:<имя>:db`), имена переменных окружения (`STANDKIT_SECRET__…`), имя
контейнера и `db_name` — иначе таблица соответствия перестаёт быть верной, а
она и так самая частая причина ошибок.

## Критерий приёмки

Оператор регистрирует стенд за агентом с первого раза, не задавая вопросов по
полям и не открывая исходники.
