# GAP-003 — адрес Redis живёт в нетипизированном `extra` и нигде не подсказан

- **Область:** модель реестра, хаб, документация
- **Приоритет:** средний
- **Заведён:** 18.08.2026
- **Статус:** ✅ закрыт — 0.8.0, PR #34
- **Как закрыт:** `redis_host: str` / `redis_port: int` подняты в поля `Stand`,
  чтение из `extra` оставлено фолбэком — реестры, заполненные до 0.8.0,
  продолжают работать без правок. `Stand.validate()` ловит половину пары и
  порт вне диапазона. Поля добавлены в форму регистрации и в
  `projects.sample.json`. `_probe_redis` кладёт в
  `StandStatus.details["redis_reason"]` текст «адрес Redis не задан в реестре»
  для `unknown` и «Redis не отвечает на …» для `down` — в UI это два разных
  состояния, а не один прочерк. Глубокая проба (`PING`) по-прежнему заглушка,
  см. [BACKLOG.md](../BACKLOG.md).

## Симптом

Колонка «Redis» в дашборде показывает `—` (`unknown`) на стенде, у которого
Redis есть и работает. Оператор не понимает, это «не настроено», «не поддержано»
или «сломалось»; в форме регистрации полей Redis нет, в модели `Stand` их тоже
нет — искать нечего.

Рабочий путь: дописать в запись стенда в `projects.json` два ключа

```json
"redis_host": "10.0.0.10",
"redis_port": 6379
```

и перезапустить агента (реестр читается один раз при старте).

## Почему так

`_probe_redis` (`standkit/health.py`) читает адрес из **`stand.extra`**:

```python
redis_host = stand.extra.get("redis_host")
redis_port = stand.extra.get("redis_port")
if not (redis_host and redis_port):
    return ProbeState.UNKNOWN
```

`extra` — это forward-compatibility мешок для чужих ключей (`Stand.from_dict`
складывает туда всё, чего нет в полях датакласса), чтобы round-trip
чтение→запись ничего не терял. Проба Redis оказалась единственным штатным
потребителем этого мешка, и в результате:

- поля не типизированы и не валидируются (`redis_port` приводится `int()` уже в
  пробе — строка «шесть тысяч» упадёт внутри пробы, а не на валидации записи);
- их нет ни в форме регистрации, ни в `projects.sample.json`;
- `UNKNOWN` не отличается в UI от «проба не поддержана».

## Что сделать

1. Поднять `redis_host: str = ""` / `redis_port: int = 0` в поля `Stand`
   (по образцу `db_host` / `db_port`), оставив чтение из `extra` как фолбэк —
   иначе у существующих реестров проба отвалится.
2. Провалидировать пару в `Stand.validate()`: задан один ключ без второго —
   явная ошибка, а не молчаливый `unknown`.
3. Добавить поля в форму регистрации (см.
   [GAP-001](GAP-001-registry-fields-out-of-hub-form.md)) и в
   `projects.sample.json`.
4. В UI различать «не настроено» и «настроено, но недоступно»: у `unknown`
   давать подсказку «адрес Redis не задан в реестре».
5. В подсказке предупредить про адрес **с точки зрения хоста, где живёт агент**:
   Redis внутри compose без проброса наружу даст `down`, а не `unknown` — та же
   грабля, что уже описана в кукбуке для `stand_host`.

## Критерий приёмки

Стенд с Redis настраивается из формы, показывает `ok`; стенд без Redis показывает
`unknown` с текстом «адрес не задан». Реестры, где ключи лежали в `extra`,
продолжают работать без правок.

## Связанное

- глубокая проба Redis (`PING`) — по-прежнему заглушка `SKIPPED`, см.
  [BACKLOG.md](../BACKLOG.md), раздел «Health-пробы».
