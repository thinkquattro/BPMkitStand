# GAP-005 — кукбук не описывает секрет агента на стороне хаба

- **Область:** документация (`standkit_hub/web/cookbook.html`)
- **Приоритет:** средний
- **Заведён:** 18.08.2026
- **Статус:** ✅ закрыт — 0.8.0, PR #34
- **Как закрыт:** в кукбук (раздел 06) добавлен подраздел «Токен агента живёт
  в двух местах»: симметрия «один ref — два хоста», формула имени переменной,
  таблица примеров, грабля «переменная задаётся ДО старта хаба» (ярлык под
  `pythonw` наследует окружение на момент создания процесса), рекомендация
  keyring для постоянной работы и абзац про readonly-токен.

## Симптом

Кукбук подробно объясняет, как задать токены **на хосте агента** (`agent.env`,
формула имени переменной, права на файл). Про **вторую половину пары** —
хаб, который этим токеном ходит к агенту, — не сказано ничего. Оператор
регистрирует стенд, видит в дашборде ошибку про секрет и не понимает, что
токен нужно завести ещё раз, на своей машине.

## Почему так

`FederatedClient.status` резолвит `agent_secret_ref` через
`standkit.secrets.get_secret()` **в процессе хаба**, то есть на машине
оператора. Цепочка резолва (`standkit/secrets.py`): переменная окружения
`STANDKIT_SECRET__<REF>` → keyring → фолбэк. Симметрия «один и тот же токен
живёт на двух хостах» нигде не проговорена, а keyring на Windows и env на
Linux-сервере выглядят как разные механизмы.

## Что сделать

Добавить в кукбук врезку «Токен агента живёт в двух местах» и рецепт для
стороны хаба (примеры анонимизированные).

1. Один и тот же control-токен: на хосте агента — в `agent.env`, на машине
   оператора — в keyring или в окружении процесса хаба. Ref в обоих реестрах
   один: `standkit:stand-a:agent-token`.
2. Формула имени переменной та же: `STANDKIT_SECRET__` + ref в верхнем
   регистре, все не-буквенно-цифровые символы → `_`.

   | Ссылка на секрет | Переменная окружения |
   |---|---|
   | `standkit:stand-a:agent-token` | `STANDKIT_SECRET__STANDKIT_STAND_A_AGENT_TOKEN` |
   | `standkit:client-uat:agent-readonly-token` | `STANDKIT_SECRET__STANDKIT_CLIENT_UAT_AGENT_READONLY_TOKEN` |

3. **Грабля, ради которой всё это пишется:** переменная должна быть задана
   **до** старта хаба. Заданная в другом окне терминала (или после запуска
   ярлыком под `pythonw`) она в процесс не попадёт, и дашборд будет показывать
   ошибку секрета при, казалось бы, выставленном значении. Для постоянной
   работы — keyring (`pip install standkit[secrets]`, кнопка «Задать секрет…»
   в «Настройках»), а не env одной сессии.
4. Проговорить, что дашборд, запущенный ярлыком, наследует окружение **на
   момент создания процесса** — после смены токена хаб нужно перезапустить.
5. Упомянуть readonly-токен: если хабу нужен только просмотр, ref может
   указывать на readonly-токен агента — управляющие кнопки тогда честно
   получат отказ, а не будут работать «на всякий случай» с полными правами.

## Критерий приёмки

Оператор поднимает связку хаб + агент по одному разделу кукбука, без вопроса
«а где хаб берёт токен».
