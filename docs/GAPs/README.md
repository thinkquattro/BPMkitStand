# GAPs — расхождения между продуктом и ожиданием оператора

Папка для **гэпов**: мест, где код формально работает по спецификации, но
оператор всё равно приходит к неверному результату — потому что нужное поле
негде задать, диагноз не выводится в интерфейсе или рецепт не описан в
документации.

Чем это отличается от соседних документов:

| Документ | О чём |
|---|---|
| [BACKLOG.md](../BACKLOG.md) | «упомянуто в коде, но не реализовано» — заглушки, зарезервированные значения, задел |
| [ROADMAP.md](../ROADMAP.md) | порядок крупных работ по версиям |
| **GAPs/** | **работающий код + неработающий сценарий оператора**: настройка недоступна, отказ не объяснён, рецепт не задокументирован |

Гэп попадает сюда, когда выполняются оба условия:

1. поведение кода **корректно** и соответствует докстрингу/тестам;
2. оператор, действуя разумно, всё равно получает не тот результат — и узнаёт
   причину только из чужой подсказки или чтения исходников.

## Правила ведения

- один гэп — один файл `GAP-NNN-краткое-имя.md`, номера не переиспользуются;
- обязательные разделы: **Симптом**, **Почему так**, **Что сделать**,
  **Критерий приёмки**;
- примеры — только **анонимизированные**: `stand-a`, `client-uat`,
  `example-host`, `10.0.0.10`. Реальные имена стендов, хостов и адреса
  заказчиков в публичный репозиторий не попадают;
- закрытый гэп не удаляется: в шапке проставляется «Закрыт: <версия>, <PR>» —
  история решения ценнее чистоты списка.
