# GAP-007 — служебный запуск падает сырым traceback, а «слушаю …» печатается до готовности

- **Область:** агент, запуск и диагностика
- **Приоритет:** средний
- **Заведён:** 18.08.2026 (живой прогон развёртывания на Ubuntu 24.04, standkit 0.7.0)
- **Статус:** ✅ закрыт — 0.8.0 (не выпущено), PR #PRNUM
- **Как закрыт:** в `standkit_agent/__main__.py` появились `resolve_agent_paths`
  (дефолты `~/.standkit/…` разворачиваются до вызова) и `preflight_paths` —
  проверка `run_dir`/`log_dir`/аудит-файла реальной пробной записью ДО печати
  «слушаю …» и до открытия сокета. Отказ — одна строка с путём, пользователем
  и нужным флагом, код возврата `1`, без traceback (по образцу
  `validate_bind_security`). Отдельная ветка для сервисного аккаунта без
  `$HOME`: не пытаемся создавать `~/.standkit`, а сразу называем все три
  обязательных флага. Занятый порт и отказ прав на bind тоже превращены в
  одну понятную строку. Шаблон `standkit-agent.service` задаёт все три пути
  явно и объясняет комментарием, почему.

## Симптом

Оператор переводит проверенный вручную агент под `systemd` с выделенным
сервисным аккаунтом (`useradd --system --no-create-home`) и получает в журнале
последовательность, которая читается как «стартовал и сразу упал»:

```
python[5097]: PermissionError: [Errno 13] Permission denied: '/opt/standkit/logs/audit.log'
python[5097]: [standkit-agent] слушаю 127.0.0.1:8765 (tls=off), реестр=…, стендов=2
systemd[1]: standkit-agent.service: Main process exited, code=exited, status=1/FAILURE
```

Строка «слушаю …» напечатана **после** исключения, хотя сокет не открывался
вовсе. Второй вариант того же — сервисный аккаунт без домашнего каталога и без
явных `--run-dir/--log-dir/--audit-log`:

```
[standkit-agent] слушаю 127.0.0.1:8766 (tls=off), реестр=/home/standkit/.config/BPMkit/projects.json, стендов=0
Traceback (most recent call last):
  …
  File "/usr/lib/python3.12/pathlib.py", line 1313, in mkdir
    os.mkdir(self, mode)
PermissionError: [Errno 13] Permission denied: '/home/standkit'
```

Из вывода не следует ни что именно недоступно с точки зрения агента, ни что
делать. Оператор идёт читать исходники или трактует падение как баг установки.

Тот же класс — занятый порт: `OSError: [Errno 98] Address already in use`
прилетает голым traceback, и снова после строки «слушаю …».

## Почему так

1. `standkit_agent/__main__.py` печатает строку «слушаю …» до вызова
   `run_server`, а фактическое создание аудит-логгера
   (`server.run_server` → `audit.build_audit_logger`) и каталогов run/log
   происходит позже. Порядок вывода в журнале перепутан с порядком событий.
2. Ошибки файловых путей не перехватываются: `PermissionError` из
   `logging.FileHandler` / `Path.mkdir` уходит наружу голым traceback. Для
   остальных предусловий у агента как раз есть аккуратный отказ — `SecretError`
   печатается одной понятной строкой с именем переменной, `validate_bind_security`
   объясняет fail-closed и предлагает три варианта.
3. Дефолты `--run-dir/--log-dir/--audit-log` (`~/.standkit/…`) рассчитаны на
   интерактивного пользователя. У сервисного аккаунта с `--no-create-home`
   каталога `$HOME` нет вовсе, и дефолт заведомо нерабочий — но узнаётся это
   только по факту падения.

## Что сделать

1. Проверять доступность `run_dir`, `log_dir` и файла аудита **до** печати
   «слушаю …» и до открытия сокета, по образцу `validate_bind_security`:
   отказ — одна строка вида
   `[standkit-agent] Отказ старта: каталог логов /opt/standkit/logs недоступен
   на запись пользователю standkit — задайте --log-dir или выдайте права`.
2. Перехватывать `OSError/PermissionError` на этих путях и возвращать
   ненулевой код без traceback (traceback оставить под `--debug`, если он
   появится).
3. Если `$HOME` не существует, а соответствующий флаг не задан — не пытаться
   создавать `~/.standkit`, а сразу сказать, какой флаг обязателен для
   служебного запуска.
4. В шаблон `standkit_agent/deploy/standkit-agent.service` добавить
   комментарий, что все три пути задаются явно именно поэтому.

## Критерий приёмки

Запуск от сервисного аккаунта с недоступным каталогом логов завершается кодом
`1`, одной понятной строкой с путём, пользователем и подсказкой, без traceback
и без строки «слушаю …». Прежнее поведение при корректных путях не меняется.
