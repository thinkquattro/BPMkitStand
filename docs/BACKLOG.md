# Бэклог standkit / BPMkitStand

Честный список того, что **упомянуто в коде, но ещё не реализовано / не
настроено** (каркас, заглушки, зарезервированные значения), с точной ссылкой на
место в коде. Цель — чтобы пользователь пакета и разработчик не принимали
«задел» за готовую фичу.

Метка **[упомянут в коде]** = в коде есть символ/ветка/поле, но реального
поведения за ним нет (или оно возвращает заглушку).

Порядок дорожной карты — см. [ROADMAP.md](ROADMAP.md). Остаточная безопасность
агента — `SECURITY.md` §6.

## Транспорты подключения к стенду

| Пункт | Статус | Упомянут в коде |
|------|--------|-----------------|
| Транспорт **`ssh`** | зарезервирован в enum, реализации нет → `NotImplementedError` | `standkit/models.py::Transport.SSH` («задел на будущее»); фолбэк-`raise` в `standkit_hub/client.py::FederatedClient.status/_dispatch_action/logs` |
| Транспорт **`winrm`** | то же | `standkit/models.py::Transport.WINRM`; там же в `client.py` |

Рабочие транспорты — только `local` и `agent` (оба реализованы; в UI регистрации
предлагаются только они). `ssh`/`winrm` достижимы лишь ручной правкой
`projects.json` и упадут с `NotImplementedError`.

## Health-пробы

| Пункт | Статус | Упомянут в коде |
|------|--------|-----------------|
| Глубокая проба БД (`SELECT 1` через psycopg2/pyodbc) | заглушка, всегда `SKIPPED`; флаг `deep_db` из хаба не передаётся | `standkit/health.py::db_deep_check`, параметр `check_stand(deep_db=…)` |
| Глубокая проба Redis (`PING` через redis-py) | заглушка, всегда `SKIPPED` | `standkit/health.py::redis_deep_check`, `check_stand(deep_redis=…)` |
| `last_deploy` (состояние последнего деплоя) | всегда `UNKNOWN`, источник данных не определён, в UI не выводится | `standkit/health.py::check_stand` (комментарий `last_deploy`), `standkit/models.py::StandStatus.last_deploy` |

Рабочие пробы (без заглушек): процесс (pid/бэкенд), HTTP, БД/Redis по **открытому
TCP-порту** — их достаточно для дашборда.

## Жизненный цикл (kestrel)

| Пункт | Статус | Упомянут в коде |
|------|--------|-----------------|
| Polling готовности веб-хоста после `start()` | не реализован (возвращается pid; готовность проверяется отдельно) | `standkit/lifecycle.py` (докстринг модуля) |
| Блокировка pidfile от гонки двух `start()` | не реализована | там же |
| Восстановление «потерянного» pidfile (сверка по cmdline) | не реализовано | там же |
| Доп. окружение процесса (`ASPNETCORE_ENVIRONMENT` и т.п.) | «зона расширения следующей итерации» | `standkit/lifecycle.py::_kestrel_start` |
| Graceful stop (SIGTERM→таймаут→SIGKILL / CTRL_BREAK_EVENT) | сейчас безусловное завершение | `standkit/platform.py::stop` |
| Windows Job Object / Linux double-fork | упрощённо (CREATE_NO_WINDOW / setsid) | `standkit/platform.py` (докстринг модуля) |

## Логи

| Пункт | Статус | Упомянут в коде |
|------|--------|-----------------|
| Обработка ротации лог-файла в `follow()` | не реализована (при пересоздании файла позиция «уезжает») | `standkit/logs.py::follow` |
