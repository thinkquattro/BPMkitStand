# Бэклог standkit / BPMkitStand

Честный список того, что **упомянуто в коде, но ещё не реализовано / не
настроено** (каркас, заглушки, зарезервированные значения), с точной ссылкой на
место в коде. Цель — чтобы пользователь пакета и разработчик не принимали
«задел» за готовую фичу.

Метка **[упомянут в коде]** = в коде есть символ/ветка/поле, но реального
поведения за ним нет (или оно возвращает заглушку).

Порядок дорожной карты — см. [ROADMAP.md](ROADMAP.md). Остаточная безопасность
агента — `SECURITY.md` §6.

## Транспорты подключения к стенду

| Пункт | Статус | Упомянут в коде |
|------|--------|-----------------|
| Транспорт **`ssh`** | зарезервирован в enum, реализации нет → `NotImplementedError` | `standkit/models.py::Transport.SSH` («задел на будущее»); фолбэк-`raise` в `standkit_hub/client.py::FederatedClient.status/_dispatch_action/logs` |
| Транспорт **`winrm`** | то же | `standkit/models.py::Transport.WINRM`; там же в `client.py` |

Рабочие транспорты — только `local` и `agent` (оба реализованы; в UI регистрации
предлагаются только они). `ssh`/`winrm` достижимы лишь ручной правкой
`projects.json` и упадут с `NotImplementedError`.

## Health-пробы

| Пункт | Статус | Упомянут в коде |
|------|--------|-----------------|
| Глубокая проба БД (`SELECT 1` через psycopg2/pyodbc) | заглушка, всегда `SKIPPED`; флаг `deep_db` из хаба не передаётся | `standkit/health.py::db_deep_check`, параметр `check_stand(deep_db=…)` |
| Глубокая проба Redis (`PING` через redis-py) | заглушка, всегда `SKIPPED` | `standkit/health.py::redis_deep_check`, `check_stand(deep_redis=…)` |
| `last_deploy` (состояние последнего деплоя) | всегда `UNKNOWN`, источник данных не определён, в UI не выводится | `standkit/health.py::check_stand` (комментарий `last_deploy`), `standkit/models.py::StandStatus.last_deploy` |

Рабочие пробы (без заглушек): процесс (pid/бэкенд), HTTP, БД/Redis по **открытому
TCP-порту** — их достаточно для дашборда.

## Жизненный цикл (kestrel)

| Пункт | Статус | Упомянут в коде |
|------|--------|-----------------|
| Polling готовности веб-хоста после `start()` | не реализован (возвращается pid; готовность проверяется отдельно) | `standkit/lifecycle.py` (докстринг модуля) |
| Блокировка pidfile от гонки двух `start()` | не реализована | там же |
| Восстановление «потерянного» pidfile | **реализовано** — поиск владельца порта, валидация (порт + allowlist образа + рабочий каталог внутри `stand_dir`) и усыновление с подтверждением | `standkit/adopt.py`, `standkit/lifecycle.py::adopt` |
| Доп. окружение процесса (`ASPNETCORE_ENVIRONMENT` и т.п.) | «зона расширения следующей итерации» | `standkit/lifecycle.py::_kestrel_start` |
| Graceful stop (SIGTERM→таймаут→SIGKILL / CTRL_BREAK_EVENT) | **реализовано** — эскалация мягко → таймаут → жёстко | `standkit/platform.py::stop` |
| Рабочий каталог процесса для WOW64 (32-битный стенд под 64-битным Python) | не реализовано — усыновление таких процессов даёт честный отказ | `standkit/adopt.py::_windows_process_cwd` |
| Windows Job Object / Linux double-fork | упрощённо (CREATE_NO_WINDOW / setsid) | `standkit/platform.py` (докстринг модуля) |

## Хаб / клиент

| Пункт | Статус | Упомянут в коде |
|------|--------|-----------------|
| Параллельный опрос агентов | **реализовано** — `ThreadPoolExecutor`, порядок результатов сохраняет порядок реестра | `standkit_hub/client.py::FederatedClient.status_all` |
| Кэш/дебаунс частых опросов | **реализовано** — фоновый поллер держит снапшот состояния, конфиг и реестр кэшируются по отпечатку файла | `standkit_hub/poller.py`, `standkit_hub/server.py::build_snapshot` |
| Ярлык на рабочем столе для **macOS** | осознанно не реализовано — возвращается понятный статус | `standkit_hub/shortcut.py` (докстринг) |
| Нативный трей (иконка со сводным состоянием, баллоны при падении) | не реализовано — потребовало бы `pystray`/`Pillow` против инварианта stdlib-only. Вместо него PWA-установка и компактный режим `?view=compact` | `standkit_hub/web/manifest.webmanifest` |
| Автозапуск хаба при входе в систему | не реализовано; механика ярлыка есть | `standkit_hub/shortcut.py` |

| Остановка хаба из интерфейса (кнопка «Завершить работу диспетчера») | не реализовано — единственный штатный способ Ctrl+C недоступен при запуске ярлыком (консоли нет) | `standkit_hub/__main__.py` (обработка `KeyboardInterrupt`) |

## Приёмка

| Пункт | Статус |
|------|--------|
| **Docker** бэкенд (одиночный контейнер + compose) | **живая приёмка проведена 17.08.2026** на Docker Engine 29.6.1: 50 проверок основного цикла (start/stop/restart по фактическому `State.StartedAt`, логи, health, идемпотентность, негативы, работа без `docker` в PATH) + 6 проверок граничных состояний (paused, crash-loop, exited, подстрочные имена сервисов, кириллица в логах). Вскрыла два ложных «стенд жив» — исправлены в этой же ветке (см. CHANGELOG) |
| **k8s** бэкенд | **живая приёмка проведена 17.08.2026** на кластере k3s 1.30 (k3d): 28 проверок — scale/rollout restart с проверкой пересоздания подов, `readyReplicas`, `k8s_replicas`, логи, NodePort-проба, негативы по деплойменту/namespace/контексту/PATH. Вскрыла ложное «жив» при нуле реплик — исправлено |
| **IIS** бэкенд | юнит-тесты на моках зелёные, **живая приёмка не проводилась**: нужен Windows-хост с ролью IIS. Тесты: `tests/test_hosting.py` (`monkeypatch` `subprocess.run`) |
| Контур для повторной приёмки k8s | на Windows с **cgroup v1** (проверить: `docker info --format {{.CgroupVersion}}`) Kubernetes ≥1.32 не поднимается — `kind` с `kindest/node:v1.36.1` падает на `kubeadm init`, k3s 1.35 не доходит до CoreDNS. Рабочий вариант — k3d с `--image rancher/k3s:v1.30.6-k3s1`; после создания кластера поправить kubeconfig: k3d прописывает `host.docker.internal`, нужен `kubectl config set-cluster <ctx> --server=https://127.0.0.1:<порт из docker port k3d-<cluster>-serverlb>` |

### Остатки после приёмки 17.08.2026 (не блокеры релиза)

| Пункт | Статус |
|------|--------|
| Контейнер в crash-loop | `is_running` отражает мгновенное состояние (`State.Status`), поэтому у контейнера с `--restart always`, падающего каждую секунду, вердикт колеблется между замерами. Честно, но для витрины бесполезно: нужен отдельный признак «перезапускается» по `RestartCount`/`State.Status == restarting`, чтобы UI показывал «краш-луп», а не мигал. У k8s этот случай уже отрабатывается верно через `readyReplicas` |
| Контракт `read_logs` при отсутствующем CLI | `DockerBackend` возвращает `None`, `KubernetesBackend` бросает `HostingError`. Протокол `HostingBackend` этого не фиксирует — привести к одному поведению |
| `KubernetesBackend.stop` | возвращает `False` по ненулевому rc без объяснения причины; `DockerBackend.stop` в том же случае бросает `HostingError` с текстом. Молчаливый `False` неотличим от «остановили, но не подтвердили» |
| `read_logs` при нескольких репликах (k8s) | `kubectl logs deployment/X` читает один под, выбранный самим kubectl — часть логов не видна и не сказано, чья |
| `restart` (k8s) не ждёт готовности | `rollout restart` возвращается мгновенно; вызывающему нужен свой `rollout status`, иначе «перезапустили» = «попросили перезапустить» |
| Усыновление стенда (kestrel) | **живая приёмка проведена** на реальном стенде, поднятом мимо диспетчера: поиск владельца порта, признание своего стенда и отказ для чужого, отсутствие действий без подтверждения, остановка по подтверждению, протухший pidfile. Именно она вскрыла, что на Windows рабочий каталог процесса приходится читать из PEB — путь к стенду не встречается ни в `ExecutablePath`, ни в командной строке |
| Усыновление стенда (IIS) | не проверено на живом контуре: автоопределение сайта, снятие зависшего `w3wp`, различение «сайт остановлен / пул остановлен / порт держит http.sys» |
