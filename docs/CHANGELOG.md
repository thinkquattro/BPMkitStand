# Changelog — standkit / BPMkitStand

Формат — [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/); версии —
[SemVer](https://semver.org/lang/ru/). Даты — 2026 год.

## [0.6.1] — 2026-07-27

### Исправлено
- **Повторный запуск по ярлыку больше не поднимает второй диспетчер.** Ярлык
  стартует хаб через `pythonw.exe`, окна нет, а закрытие браузера процесс не
  останавливает — idle-shutdown у хаба нет. Поэтому второй клик по ярлыку
  запускал ещё один экземпляр: два фоновых поллера дёргали health-пробы и
  внешние команды бэкендов хостинга над одним `projects.json`, а окно
  открывалось на другом origin со своей копией localStorage (сбрасывалась
  тема). На Windows было хуже, чем предполагалось: из-за `SO_REUSEADDR` bind
  на уже слушаемый 8770 проходил успешно, и два хаба молча делили один порт.
  Теперь перед стартом проверяется, не работает ли диспетчер уже — если да,
  просто открывается браузер на нём. Откат на свободный порт сохранён для
  случая, когда 8770 занял чужой сервис.
- **Дашборд честно сообщает, что диспетчер остановлен.** Раньше вкладка с
  умершим хабом продолжала показывать последний снапшот как живой, а
  единственными признаками были красная точка в углу и браузерное
  `Failed to fetch` в тостах. Теперь показывается баннер с объяснением и тем,
  что делать, устаревшая таблица гасится, а сетевые ошибки и 401 («сессия не
  подтверждена» после перезапуска диспетчера) переведены на понятный язык.

## [0.6.0] — 2026-07-27

### Добавлено
- **Усыновление стендов, поднятых вне диспетчера.** Стенд, запущенный руками
  (`dotnet BPMSoft.WebHost.dll` из консоли, скриптом, чужой сессией), теперь
  можно остановить и перезапустить: диспетчер находит владельца порта,
  проверяет, что это действительно процесс ЭТОГО стенда (порт + имя образа из
  allowlist + рабочий каталог внутри `stand_dir`), и берёт его под управление —
  **только с явного подтверждения**. Без подтверждения процесс не трогается.
  В таблице стендов появился бейдж «вне диспетчера».
- **IIS: автоопределение сайта** по physical path и биндингу для стенда,
  развёрнутого мимо диспетчера; снятие зависшего `w3wp` по pid; различение
  состояний «сайт остановлен» / «пул остановлен» / «порт держит http.sys».
- **PWA.** `manifest.webmanifest` + иконки: Chrome и Edge предлагают
  «Установить приложение» — дашборд получает отдельное окно без адресной
  строки, свою иконку в панели задач и место в Alt+Tab. Зависимостей не
  добавилось.
- **Компактный режим** `?view=compact` — узкое окно-виджет: имена стендов,
  состояния и старт/стоп. Доступен ярлыком из установленного PWA.
- `GET /api/stands?probe=0` — слепок реестра без сетевых проб, и
  `GET /api/events` — SSE-поток обновлений состояния.

### Изменено
- **Дашборд открывается мгновенно.** Раньше первый экран ждал полного обхода
  всех стендов: пробы шли последовательно, до 9 секунд на стенд, а конфиг и
  реестр перечитывались с диска на каждый запрос. Три недоступных стенда за
  firewall давали около 27 секунд серого экрана. Теперь состояние собирает
  фоновый поток, а страница рисуется сразу и обновляется по мере готовности.
- **Фиксированный порт по умолчанию — 8770** (с откатом на свободный, если
  занят). Побочный эффект прежнего эфемерного порта: браузер каждый запуск
  считал дашборд новым сайтом, из-за чего сбрасывалась выбранная тема и
  заново качалась статика.
- Тема хранится в конфиге хаба и применяется до загрузки скриптов — тёмная
  больше не мигает светлой при открытии.
- Настройка «интервал автообновления» наконец работает: раньше значение из
  формы ни на что не влияло, интервал был жёстко зашит.
- **Форма настроек разгружена**: сразу видны четыре основных поля, параметры
  федерации и демона-агента убраны под спойлеры, причём блок агента скрыт
  целиком, пока в реестре нет удалённых стендов. У полей появились пояснения
  и подсказки со значениями по умолчанию.
- Остановка стенда стала мягкой: сначала штатное завершение с ожиданием и
  только потом принудительное — стенд успевает закрыть соединения с БД и
  Redis. Раньше на Windows сразу шёл `taskkill /T /F`.
- Статика отдаётся с валидаторами кэша (`ETag`, `304`).

## [0.5.2] — 2026-07-25

### Изменено
- **IIS: жизненный цикл по Site.** Стоп/рестарт/детект работают по **Site**
  стенда; **App Pool не трогаем** (может быть общим с другими приложениями).
  App Pool задействуется только когда `iis_site` не задан. Детект «жив» — по
  состоянию сайта; открытый TCP-порт больше не маскирует остановленный сайт
  (http.sys держит порт). См. [ADR-0004](adr/0004-iis-site-scoped-lifecycle.md).
- **Читаемые ошибки внешних команд.** Вывод `appcmd`/`docker`/`kubectl`
  декодируется utf-8 → OEM (cp866) → cp1251 — больше не «кракозябры».
- **Хаб — тяжёлые логи IIS.** Панель «Текущее состояние» берёт логи только за
  сегодня и читает лишь хвост файла (до 4 МБ) — дневной IIS-лог в сотни МБ не
  грузится целиком.
- Упаковка: SPDX-выражение лицензии (`license = "MIT"`, `license-files`) —
  убран deprecation-warning setuptools.

### Добавлено
- Подсказка «запустите диспетчер от имени администратора» при ошибках `appcmd`
  из-за нехватки прав (IIS требует elevation).
- Кнопка «Обновить» даёт обратную связь (блокировка + «Обновление…» + время).
- Колонка **Redis** в таблице стендов с номером базы.
- Обратная связь и надёжность первого запуска: папка реестра создаётся при старте
  диспетчера и при первой записи.

### Исправлено
- **Честный отказ** при остановке стенда, запущенного вне диспетчера (нет
  pidfile): вместо мнимого «остановлено» — понятная ошибка.
- Логи стенда ищутся в подпапках по датам (рекурсивный листинг) — раньше хаб
  ошибочно сообщал «в каталоге нет файлов».
- Модалки не закрываются при выделении текста мышью с отпусканием за краем окна.
- Колонки таблицы не «прыгают» при смене статуса; HTTP-значение — кликабельная
  ссылка; кнопки в модалках не слипаются.
- `Ctrl+C` завершает `standkit-hub` чисто, без трейсбека `KeyboardInterrupt`.
- Дедуп SVG-ассетов; TODO-докстринги урезаны до ссылок на документацию/бэклог.
