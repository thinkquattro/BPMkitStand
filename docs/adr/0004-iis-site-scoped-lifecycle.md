# ADR-0004 — IIS: жизненный цикл по Site (App Pool не трогаем)

- Статус: **Принято / реализовано** (v0.5.2, 2026-07-25)
- Контекст-владелец: Владимир Терновский
- Связано: [ADR-0001](0001-hosting-backends.md) (вводит IIS-бэкенд), [HOSTING.md](../HOSTING.md)

## Контекст и проблема

Первая реализация IIS-бэкенда (ADR-0001) на **стоп/рестарт** трогала и **сайт, и
App Pool** (`stop apppool` + `stop site`; рестарт — `recycle apppool`). На живом
стенде вскрылись три проблемы:

1. **App Pool может быть общим** с другими приложениями. Остановка/рециклинг пула
   кладёт и их — диспетчер обязан гасить **только стенд**, а не «полстраницы IIS».
2. **Детект «жив» врал.** IIS/`http.sys` держит порт 80/443 на уровне ОС даже у
   **остановленного** сайта (отдаёт 503). TCP-фолбэк показывал остановленный
   стенд как «up».
3. **Ошибка `appcmd` была нечитаемой** (OEM-кодировка cp866 декодировалась как
   UTF-8 → «кракозябры»), а её первопричина — **нехватка прав администратора**
   (`appcmd` читает `…\inetsrv\config\redirection.config`) — не была очевидна.

## Решение

**«Стенд в IIS» = его Site.** Диспетчер управляет **сайтом** и не трогает App
Pool (пул — потенциально общая инфраструктура). Пул задействуется только как
единственный хэндл, когда `iis_site` не задан.

- **stop** → `appcmd stop site /site.name:<site>` (только сайт); при отсутствии
  `iis_site` — `stop apppool`.
- **restart** → `stop site` + `start site` (App Pool **не рециклим**; recycle
  пула — только когда сайт не задан).
- **start** → `start apppool` (если задан, чтобы сайт мог обслуживаться) +
  `start site` — запуск не разрушителен для соседей.
- **is_running** → состояние **сайта** (`list site <site> /text:state == Started`);
  при отсутствии сайта — состояние пула. TCP-фолбэк — **только** если `appcmd`
  не дал определённого состояния (иначе открытый порт http.sys маскировал бы
  остановленный сайт).

Смежно (тот же цикл, v0.5.2):

- **OEM-декод** вывода внешних команд: bytes → utf-8 → OEM (cp866) → cp1251
  (`standkit/hosting.py::_decode_console`) — читаемые сообщения.
- **Подсказка про elevation**: при ошибках нехватки прав (`redirection.config`,
  «отказано в доступе», код 1168, `0x80070005`) к тексту добавляется «запустите
  диспетчер от имени администратора» (`_appcmd_checked`). Docker/k8s не затронуты.

## Реализация

`standkit/hosting.py::IisBackend.{stop,restart,is_running}`,
`_decode_console`/`_oem_encoding`, `_appcmd_checked`. Обработчик действий хаба
ловит `HostingError` и отдаёт понятный текст (`standkit_hub/server.py`). Тесты —
`tests/test_hosting.py` (site-scoped стоп/рестарт, детект по сайту, OEM-декод,
подсказка про админа).

## Требование эксплуатации

Диспетчер (`standkit-hub`) для IIS-операций **должен быть запущен «от имени
администратора»** — `appcmd` требует elevation; членства в `IIS_IUSRS`
недостаточно. См. [HOSTING.md](../HOSTING.md) → «Требования».

## Границы

- Остановка только сайта прекращает приём запросов, но рабочий процесс пула
  (`w3wp`) может дожить до idle-timeout, если пул обслуживает и другие приложения
  — это осознанный компромисс ради «не задеть соседей». Опция «гасить выделенный
  пул» с защитой «если пул общий — отказ» — возможное расширение (бэклог).
