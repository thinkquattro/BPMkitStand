# ADR-0003 — Браузинг и скачивание логов удалённых стендов

- Статус: **Предложено** (не реализовано) — приоритетный бэклог
- Контекст-владелец: Владимир Терновский
- Связано: [ADR-0001](0001-hosting-backends.md) (ссылается сюда), [REMOTE_STANDS.md](../REMOTE_STANDS.md), [BACKLOG.md](../BACKLOG.md)

> Этот ADR фиксирует **намеченное** решение. Реализации в коде пока нет —
> зафиксирован как «должен быть на месте» в связке с ADR-0001, который на него
> ссылается.

## Контекст и проблема

В дашборде есть «Открыть папку логов» — но это `os.startfile`/`xdg-open`
(`standkit_hub/logs_browser.py::open_folder`), т.е. открытие папки в файловом
менеджере **на машине оператора**. Для **удалённого** стенда (`transport=agent`)
открывать нечего: файлы лежат на хосте агента.

При этом у стендов BPMSoft логи организованы **папками по датам** (`папка = дата`,
внутри — тяжёлые дневные файлы). Оператору нужно: увидеть **листинг**, выбрать
**дату/файл**, **посмотреть** и при необходимости **скачать** (файл целиком или
папку архивом), не выкачивая гигабайты «на всякий случай».

## Решение (намечено)

Агент отдаёт логи по HTTP; хаб даёт UI выбора/просмотра/скачивания. Все пути —
traversal-safe (как `sanitize_log_filename`).

### Новые эндпоинты агента (`standkit_agent/server.py`, scope readonly)

- `GET /stand/{name}/logs/list` — листинг папки логов: файлы/подпапки с именем
  (POSIX-путь относительно корня логов), размером и mtime; сортировка по свежести.
- `GET /stand/{name}/logs/file?path=…` — содержимое (или хвост) одного файла;
  параметры `n`/`max_bytes` как у `standkit.logs.tail`.
- `GET /stand/{name}/logs/download?path=…` — скачивание: одиночный файл как есть
  либо папка (напр. дата) ZIP-архивом; ленивое стриминг-скачивание без
  предзагрузки в память.

### Хаб (`standkit_hub/*`)

- Панель логов: выбор источника → **выбор даты/файла из листинга агента** →
  просмотр хвоста → кнопка «Скачать» (файл / папку-архив).
- Для локального стенда — то же поверх `standkit.logs`/`logs_browser`
  (единый UI, разные бэкенды доставки).

### Затрагиваемые модули

`standkit_agent/server.py` (эндпоинты + traversal-guard + стриминг),
`standkit_hub/client.py`/`server.py`/`web/*` (UI листинга/просмотра/скачивания),
`standkit/logs.py` (переиспользование `tail(max_bytes=…)`; уже есть).

## Границы и риски

- **Безопасность**: только scope `readonly`; строгая защита от path traversal
  (корень логов стенда — единственная разрешённая зона); лимиты размера ответа.
- Большие архивы папок — стримить, не собирать в память; тайм-ауты/лимиты.
- Не ломать текущий локальный «Открыть папку логов» — он остаётся для локального
  стенда.

## Статус реализации

- [ ] Эндпоинты агента `logs/list` · `logs/file` · `logs/download`.
- [ ] UI хаба: листинг + выбор даты/файла + просмотр + скачивание.
- [ ] Тесты (traversal-safe, стриминг, листинг с датами).
