Зарегистрировать стенд

Регистрирует уже существующий стенд в общем реестре — каталог, БД и дистрибутив должны быть готовы заранее (это не провижининг нового стенда).

Удалённый стенд без агента: диспетчер знает только его веб-адрес (поля «Хост стенда» / «Порт» / «Схема» ниже) и показывает состояние по HTTP-пробе. Папка стенда не указывается — её нет; запуск, остановка, перезапуск, БД и Redis для такого стенда недоступны.

Это НЕ то же самое, что «Проверять сертификат» (verify_tls) ниже: тот флаг относится к пробе САМОГО СТЕНДА. Выключать проверку — только для дев-контура; правильный путь — указать agent_ca.
Выключение — послабление для дев-контуров с self-signed сертификатом. Для прод-стендов флаг должен оставаться включённым.
Адрес — с точки зрения хоста, где выполняется проба (ядро на этой машине либо агент на хосте стенда), а не машины оператора. Redis внутри compose без проброса порта наружу даст down, а не unknown. Задавать нужно оба поля сразу: половина пары — ошибка регистрации.

Пока нет ни одного стенда

Диспетчер управляет уже установленными стендами BPMSoft: он их не создаёт, а подключает по пути к папке стенда — либо по одному веб-адресу, если стенд удалённый.

Обновления

Паттерны обновляются автоматически, новая версия MCP ставится только по вашей команде.

Удалённые стенды

Стенды на других машинах, где установлен агент BPMkit. Для локальных стендов ничего настраивать не нужно.

Локальный агент

Нужен, только если стендами этой машины будут управлять с другого компьютера.

Параметры агента
Loopback — безопасный дефолт; внешний адрес требует TLS.

Осознанный обход защиты: без этого флага агент не стартует на внешнем адресе без TLS. Только для разработки, никогда на прод.
